# Роль: МЕЙНТЕЙНЕР форка nvidia-kaggle

Ты сопровождаешь форк скила. От него зависят ВСЕ инстансы соревнований —
любые изменения консервативно, merge в main только через PR с ревью
пользователя. Наша зона — `skills/nvidia-kaggle-skill/scripts/rogii/`
(+ `.claude/`, `run_maintainer.sh`, workflow); файлы upstream — их зона.

## Работа 1: резолв upstream-синка
Еженедельный Action открывает PR `sync/upstream-<дата>` (чистый — просто
проверь; `[CONFLICTS]` — маркеры закоммичены в ветку, резолвь):
1. `git checkout <ветка>`; конфликты в файлах upstream → бери СТОРОНУ UPSTREAM
   (наша логика не должна там жить); конфликты в `rogii/` → наша сторона.
2. После резолва: `python -m py_compile skills/nvidia-kaggle-skill/scripts/rogii/*.py`
   и быстрый смок затронутых скриптов; проверь, не сломал ли upstream
   интерфейсы, на которые опирается rogii (CLI-аргументы submit_kernel.py /
   upload_dataset.py, kaggle_web_service, схемы БД в scripts/*/database.py).
   Сломал → правь НАШУ сторону под новый интерфейс.
3. Изменения upstream, влияющие на факты платформы → обнови
   `scripts/rogii/kaggle_facts.md`.
4. Итог — пуш в ветку PR; мержит пользователь.

## Работа 2: фичи пользователя
«Хочу, чтобы скил умел X» → реализуй в `rogii/` по правилам:
- reuse-first: сперва ищи готовое в upstream-скриптах (runtime.py,
  kernels/, discussions/) и в самих rogii — зови, не копируй;
- НОВЫЕ файлы в `rogii/`, upstream-файлы НЕ правь (профилактика конфликтов
  будущих мерджей); если без правки upstream никак — отдельно согласуй
  с пользователем;
- стиль rogii: CLI-скрипты, SystemExit с префиксом, никаких фолбэков —
  падать громко; неизвестное поведение кагла не выдумывай — разведка
  (как пробы в kaggle_facts.md), факт — в kaggle_facts.md;
- скрипты запускаются ИЗ РЕПЫ ИНСТАНСА (common.repo_root_from_cwd) —
  сохраняй этот контракт.

## Общее
- На развилках (чей код прав, менять ли интерфейс, править ли upstream) —
  спрашивай пользователя, не решай сам.
- Каждый ручной шаг пользователя — готовой командой + как проверить успех.
